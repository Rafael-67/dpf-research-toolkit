# GitHub release checklist

- [ ] Review public source, metadata, documents and fixtures for private data.
- [ ] Review historical development reports and label their status accurately.
- [ ] Replace anonymous authors and the placeholder URL in CITATION.cff with
      verified information; confirm the release date and version.
- [ ] Confirm Vite base path and Playwright URLs match the repository name.
- [ ] Enable Pages with GitHub Actions as the source.
- [ ] Obtain a successful CI run on the exact release commit.
- [ ] Confirm typecheck, unit tests, lint, production build and browser tests.
- [ ] Smoke-test the live Pages site, including hash-route reloads.
- [ ] Add the live URL to About and README.
- [ ] Create a version tag and GitHub Release with known limitations and checks.
- [ ] Reference the repository, exact release tag and Pages URL in the manuscript.

Historical test results are not current validation evidence. Institutional
data-protection review remains required before any real-study use.
